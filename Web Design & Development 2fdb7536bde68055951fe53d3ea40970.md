
## Conceptuele Uitleg

Privacy is geen enkel concept maar heeft meerdere dimensies: 

- **Individueel recht**: Je buurman hoeft niet de hele tijd naar binnen te kijken
- **Sociaal recht**: In elke context anders zijn (met je dokter deel je andere informatie dan met de buurman)
- **Democratische noodzaak**: Autonoom je mening kunnen vormen

**Kernprincipe: Contextuele integriteit** 

Privacy moet je zien als contextuele integriteit: er worden geen onverwachte dingen gedeeld met onverwachte partijen.  Bijvoorbeeld: de bakker maakt geen foto van je als je een brood koopt. 

**Waarom is dit belangrijk?** Privacy verandert met de tijd (200 jaar geleden lag je in een hotel in een bed met random mensen), maar het gaat altijd over controle.  Door de AVG is data van personen niet alleen maar een asset voor bedrijven. 

## Privacywetgeving: AVG (GDPR)

De **AVG** is eigenlijk gewoon common sense over hoe je met elkaar omgaat.  Belangrijkste principes:

### Rechtsgrondslagen

- **Toestemming**: Altijd toestemming vragen
- **Noodzakelijkheid**: Als je naar Bol gaat en iets koopt, hebben ze je adres nodig—dit is noodzakelijk voor de dienst
- **Wettelijke verplichting**: Als je een bedrijf bent moet je 7 jaar lang klantgegevens bewaren
- **Gerechtvaardigd belang**: Bij de KNVB werden wedstrijden opgenomen—hierbij geldt **doelbinding**: de KNVB mag de wedstrijden opnemen maar niet doorverkopen

### Rechten van de gebruiker

- Je mag je gegevens **inzien, corrigeren en aanvullen**
- **Recht op vergetelheid**
- **Data portabiliteit**: Je mag je data meenemen naar een andere partij

## Technische Privacy-oplossingen

**Vraagstuk**: Hoe kun je de functionaliteit krijgen die je wilt met een garantie van zoveel mogelijk privacy? 

Voorbeeld: Hoe hou je bij wie er een garage in rijdt, zonder een hele database te maken van elke auto? 

### Oplossingen

- **Hashes**: Eenrichtingsversleuteling van data
- **Blind signatures**: Cryptografische handtekeningen waarbij de ondertekenaar de inhoud niet kan zien

## Best Practices & Tips

### ✅ Do's

- **Contextuele integriteit handhaven**: Deel alleen verwachte informatie met verwachte partijen
- **Doelbinding respecteren**: Gebruik data alleen voor het doel waarvoor het verzameld is
- **Gebruikersrechten faciliteren**: Maak inzage, correctie en verwijdering mogelijk
- **Privacy by design**: Kies technische oplossingen die privacy beschermen (hashes, blind signatures)

### ❌ Don'ts

- **Data niet zien als alleen een asset**: Door de AVG is dit veranderd—data brengt ook verantwoordelijkheid
- **Geen onverwachte data-uitwisseling**: De bakker maakt geen foto van je als je een brood koopt
- **Geen purpose creep**: Gebruik data niet buiten het oorspronkelijke doel

## Conceptuele Uitleg

Deze presentatie behandelt hoe AI wordt ingezet om toegankelijkheidsproblemen voor mensen met visuele beperkingen op te lossen.  De spreker (Leonie, die blind is) demonstreert praktische AI-toepassingen die tekortkomingen van het huidige web compenseren.

De spreker ziet zichzelf als een "kanarie in een koolmijn" die test hoe AI op het web functioneert voor mensen met beperkingen.  Ze is niet tegen AI, maar wel tegen zinloos gebruik ervan—AI moet beperkingen aanvullen, niet compenseren voor luiheid van ontwikkelaars.

## Conceptuele Uitleg

Deze lezing behandelt **progressive enhancement** als ontwerpprincipe voor het moderne web.  Het kernidee: websites moeten basisfunctionaliteit bieden zonder afhankelijk te zijn van JavaScript of geavanceerde features. Een veelgebruikte analogie is dat een roltrap nog steeds werkt als trap wanneer de stroom uitvalt—zo moet het web ook functioneren. 

**Waarom is dit belangrijk?** Door te beginnen met **HTML first** en vervolgens functionaliteit laag voor laag toe te voegen, creëer je robuuste websites die voor iedereen werken, ongeacht browser, apparaat of netwerkkwaliteit.  Daarnaast is er een groeiende **anti-AI trend** waarbij designers handgeschreven en unieke elementen (zoals handgeschreven logo's) gebruiken om authenticiteit te tonen. 

Een belangrijk discussiepunt: hoewel het web open is, vindt er veel plagiaat plaats van portfolio's en creatief werk. 

## Code Voorbeelden & Syntax

### HTML First: Details Element

Het **`<details>`** element biedt native accordion-functionaliteit zonder JavaScript:

```html
<details>
  <summary>Klik om meer te lezen</summary>
  <p>Deze content is standaard verborgen maar werkt zonder JavaScript.</p>
</details>
```

### CSS: Interpolate-size voor Animaties

De **`interpolate-size`** property stelt je in staat om animaties te maken tussen `auto` en specifieke groottes:

```css
:root {
  interpolate-size: allow-keywords;
}

/* Nu kun je animeren van height: 0 naar height: auto */
.expanding-element {
  height: 0;
  transition: height 0.3s ease;
}

.expanding-element.open {
  height: auto; /* Animeert smooth dankzij interpolate-size */
}
```

### Popover API

De **Popover API** biedt native functionaliteit voor dialogen en tooltips zonder JavaScript frameworks:

```html
<!-- Knop die de popover triggert -->
<button popovertarget="my-popover">Open popover</button>

<!-- Popover element -->
<div id="my-popover" popover>
  <p>Dit is een native popover zonder JavaScript!</p>
  <button popovertarget="my-popover" popovertargetaction="hide">Sluiten</button>
</div>
```

```css
/* Styling voor de popover */
[popover] {
  padding: 1rem;
  border: 1px solid #ccc;
  border-radius: 8px;
  background: white;
}

/* Backdrop styling */
[popover]::backdrop {
  background: rgba(0, 0, 0, 0.5);
}
```

## Best Practices & Tips

### ✅ Do's

- **Progressive enhancement toepassen**: Begin met werkende HTML, voeg daarna CSS en JavaScript toe
- **HTML-first benadering**: Gebruik native HTML elementen waar mogelijk (bijv. `<details>`, popover API)
- **Moderne CSS features gebruiken**: Experimenteer met nieuwe properties zoals `interpolate-size`
- **Authenticiteit tonen**: Overweeg handgeschreven elementen in designs als reactie op AI-gegenereerde content

### ❌ Don'ts

- **Niet volledig afhankelijk zijn van JavaScript**: Basisfunctionaliteit moet zonder werken
- **Geen plagiaat plegen**: Respecteer het werk van andere designers en ontwikkelaars

## Actiepunten / Oefeningen

## Conceptuele Uitleg

Deze lezing behandelt het contrast tussen de geplande veroudering van moderne consumentenproducten en de inherente duurzaamheid van webtechnologieën.  De spreker gebruikt persoonlijke voorbeelden van kapotte huishoudelijke apparaten (stofzuiger, vaatwasser) om te illustreren hoe moderne producten opzettelijk niet repareerbaar worden ontworpen.  

**Waarom is dit belangrijk?** In tegenstelling tot fysieke producten die steeds moeilijker te repareren zijn, zijn **HTML, CSS en JavaScript** ontworpen met backwards compatibility als kernprincipe—ze zijn gebouwd om niet kapot te gaan.  Dit maakt het web een bijzonder duurzaam platform dat door de tijd heen blijft functioneren.

De spreker contrasteert dit met professionele apparatuur zoals de **Linhof supercamera**, die wel is ontworpen om lang mee te gaan ("built to last").

## Best Practices & Tips

### ✅ Do's

- **Ontwerp met duurzaamheid in gedachten**: Leer van het "built to last" principe uit professionele apparatuur
- **Gebruik de inherente stabiliteit van webstandaarden**: HTML/CSS/JS blijven door backwards compatibility werken

### ❌ Don'ts

- **Geen geplande veroudering**: Vermijd ontwerpkeuzes die code onnodig kwetsbaar maken
- **Niet meedoen aan de overvloed-cultuur**: Wees bewust van duurzaamheid in je technische keuzes
