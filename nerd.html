Web Design & Development – Moderne CSS

Custom Styling & UX

CSS is makkelijker te parsen dan JS. Veel dingen die we vroeger met libraries deden, kunnen nu native. 

/* Checkbox volledig stijlen */
input {
  appearance: none;
}

/* Smooth scroll zonder JS */
html {
  scroll-behavior: smooth;
}

/* Ruimte boven anchor links */
#target {
  scroll-margin: 100px;
}

Nils (Nine Elements) – CSS & Creativiteit

Wat bleef er hangen?

  • Figma is top, maar het beperkt je ook omdat je alleen bouwt wat de tool kan. CSS kan veel meer.
  • We bouwen vaak dezelfde saaie "hero + 3 blokjes" layouts.

De extra's:

  • FR-units zijn life voor asymmetrische grids zonder dat het breekt.
  • Gebruik steps() voor van die vette flipbook-animaties in plaats van zware video's. 
/* Grid met FR units */
.container {
  display: grid;
  grid-template-columns: 2fr 3fr auto 1fr;
}

/* Steps animatie */
.keyvisual {
  animation: stop-motion 3s steps(31, end) infinite;
}

Mijn mening: Dit was echt de leukste sessie. Het motiveerde me om meer met pure CSS te klooien in plaats van voor alles meteen Figma te pakken.

Manuel (Bol.com) – Toegankelijkheid

Wat bleef er hangen?

  • Toegankelijkheid is meer dan een checklist afvinken.
  • Je moet echt praten met mensen die een beperking hebben om te snappen hoe zij je site gebruiken.

Tips:

  • Laat de alt-tekst leeg bij plaatjes die alleen voor de sier zijn, anders leest die screenreader alles op.
  • Koppen (H1, H2) zijn super belangrijk voor navigatie; mensen skippen daarmee door je site. 
<!-- Informatief -->
<img src="product.jpg" alt="Zwarte laptop">

<!-- Decoratief -->
<img src="line.svg" alt="">

Mijn mening: Het was echt confronterend om te horen hoe vermoeiend een slechte site is voor iemand met een screenreader. Je beseft dan pas hoeveel impact je code heeft.

Hacker Filosofie & Zelf hosten

Wat bleef er hangen?

  • We zijn eigenlijk te afhankelijk van die grote Amerikaanse techbedrijven.
  • Een 'hacker' is ook gewoon iemand die alles zelf bouwt en controle houdt.

Tips:

  • Host je eigen site op een oude computer of eigen server.
  • Gebruik systeemfonts en compress je plaatjes om je site licht en duurzaam te houden. 
/* Reduced motion support */
@media (prefers-reduced-motion: reduce) {
  .header-logo {
    animation: none;
  }
}

/* Systeem fonts */
body {
  font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto;
}

Mijn mening: Een beetje een radicaal verhaal over onafhankelijkheid, maar het zette me wel aan het denken over privacy en waarom we alles maar op YouTube of Github zetten.

UX van Formulieren

Wat bleef er hangen?

  • Mensen haten formulieren, dus maak het ze zo makkelijk mogelijk.
  • Vertel mensen waarom je hun info (zoals een telefoonnummer) nodig hebt.

Tips:

  • Zet labels altijd boven de inputveldjes.
  • Wees chill met validatie: laat mensen gewoon spaties in hun postcode zetten. 
<!-- Toegankelijk formulierveld -->
<div class="form-field">
  <label for="name">Naam *</label>
  <p id="name-help">Vul je volledige naam in</p>
  <input id="name" aria-describedby="name-help" required>
</div>

Mijn mening: Super praktisch. Vooral dat ding over password managers en waarom je geen placeholders in wachtwoordvelden moet zetten was een goede eye-opener.

Browser-techniek & Geschiedenis

Wat bleef er hangen?

  • Browsers zijn mega complex en hebben aparte engines voor rendering en JS.
  • Veel oude zooi in HTML werkt nog steeds door 'backward compatibility'.

Technisch:

  • Gebruik defer voor je scripts zodat de pagina sneller laadt.
  • Vergeet je doctype niet, anders gaat je CSS raar doen in 'Quirks Mode'. 
<!-- Script loading -->
<script async src="script.js"></script>
<script defer src="script.js"></script>

<!-- Standards mode -->
<!DOCTYPE html>

Mijn mening: Goed om eens onder de motorkap te kijken. Het helpt je snappen waarom je bepaalde code op een specifieke plek moet zetten voor performance.
